Architecture · Threat Model

Threat Model

The trust boundaries, the adversaries defended against, and — explicitly — what is in scope for the POC versus deferred. The boundary that matters most: submitted inbound credentials cross from the recipient into Vault and stop there. They never enter Postgres, never enter a log, and are never returned by any operator-facing endpoint.

Defense-in-depth on the secret-bearing paths

The three secret-bearing routes — POST /api/v1/inbox/:id, POST /api/v1/shares, and GET|POST /api/v1/reveal/:token — are protected at every layer, with no single point of failure (see traefik/dynamic/security.yml):

  1. No body logging, anywhere. Traefik never logs request/response bodies; the broker's structured log emits the templated route (/api/v1/reveal/:id) only — never the raw path (which itself carries a capability token) and never the body.
  2. No header/token leakage. Traefik access logs drop request headers (no Authorization / Cookie / X-Vault-Token). Referrer-Policy: no-referrer keeps URL-embedded tokens out of the Referer header. HSTS enforced; links HTTPS-only and short-TTL.
  3. Static gate. A semgrep rule (tools/semgrep/secret-leak.yml, CI job secret-leak-scan) fails the build if any code path pipes a Vault-read value or a request body into a logger.
  4. Runtime backstop. The audit emitter throws (MetadataLeakError) before any sink sees an event whose metadata carries a forbidden key (password, value, token, …).
  5. Strict CSP on the credential surfaces. The intake portal and reveal page ship the strictest CSP of any surface — no third-party scripts, no analytics, minimal JS — built and served separately from the operator console, so a console compromise can't reach the intake/reveal DOM.
  6. The AI never sees plaintext (#66). The embedded-AI boundary consumes metadata only. Two semgrep rules in the same gate fail the build if a Vault-read value flows into a model call, or if any code under an ai/ path touches the Vault read surface. A build-breaking boundary, not a convention.

Read the deferred list as a boundary

Do not assume a deferred control is present in the POC. The POC runs on one box with file storage; it proves the load-bearing property (operator-blind inbound) and ships the tamper-evident audit chain. Everything else in the "deferred" column is target-state — tracked, sequenced, and described on the Roadmap.
